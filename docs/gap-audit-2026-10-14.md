# TST Desk gap audit: Claude Code, Claude Desktop, Cowork (public docs), 2026-10-14

This audit compares TST Desk with what Anthropic publicly documents for Claude Code, Claude Desktop and Cowork, and with the open MCP, MCPB and Agent Skills specs. It lists what TST Desk already covers, ranks the gaps that hold up, and proposes stories TD-5101 to TD-5139 for Adam to pick from. Nothing has been built.

## Method

- **Sources:** public docs and open specs only: code.claude.com/docs, platform.claude.com/docs, support.claude.com, modelcontextprotocol.io, agentskills.io and github.com/modelcontextprotocol/mcpb. No installed Anthropic software, app resources or extracted prompts were used. Anthropic's terms forbid reverse engineering their services, so this audit only covers documented, user-visible behavior, described in our own words.
- **Code reference:** commit 0d0a878 (the base of td/5014-phone-pairing), read in a separate worktree.
- **How each status was reached:**
  1. Seven area readers listed 286 documented capabilities and checked each one against the code and against docs/tst-desk-backlog.md.
  2. A separate verifier per area tried to prove each gap wrong. It searched the code under other names, re-opened the source page and checked the backlog for an existing story.
  3. A completeness sweep over the doc indexes added 30 capabilities that no area had covered, and those were verified the same way.
  4. A final pass in the main session:
     - Re-checked the top claims in the code: shell rules glob the whole command line (core/tstd/policy.py:210). MCP is pinned to protocol 2024-11-05 and sends no capabilities (core/tstd/mcp/jsonrpc.py:13,24). MCP calls time out at a fixed 30 s (jsonrpc.py:19). There are seven built-in tools and no search, question or task-list tool (core/tstd/tools/registry.py:243-442).
     - Confirmed that all 113 cited source pages resolve.
- **Totals:** 316 capabilities.
  - 56 are covered.
  - 249 are gaps: 125 confirmed and 124 partial.
  - 11 don't apply.
  - Of the gaps, 47 scored value 4-5. Those became the 39 stories below; near-duplicates were merged.
  - The other 202 gaps are listed with their scores in [the appendix](gap-audit-2026-10-14-appendix.md).
- **Caveat:** the verifiers refuted none of the reported gaps. They did reword many of them and mark them as partial. Treat each story's evidence as a strong lead and re-read the cited lines before building.
- **Scales:** value is 1-5 for TST Desk users, weighted toward local models and daily use on EZER. Size is in backlog points (1 = under an hour, 8 = several days).

## Stories

### TD-5101 — Shell rules: judge every segment of a chained command, deny first
**Size:** 5 · **Depends on:** none
**Acceptance criteria**
- [ ] A shell command is split on `;`, `&&`, `||`, `|`, newlines, `$(…)` and backticks, after stripping wrappers such as `timeout`, `nice` and `env VAR=…`. An `auto` rule applies only when every segment matches an `auto` rule.
- [ ] A `never` rule that matches any segment refuses the call, whatever narrower `auto` rule exists. `never` beats `ask` beats `auto`, and specificity only breaks ties within one effect.
- [ ] Tests cover `npm test; curl x`, `npm test && rm -rf y`, `npm test | sh`, `$(curl x)` and a wrapped `timeout 60 npm test`.
- [ ] The example rules in docs/configuration.md (about lines 1262-1280) are rewritten so they are no longer exploitable, and the change is noted in DECISIONS.md.

**Notes** — Claude Code's permission docs say a prefix rule does not cover a command chained onto it, and that deny rules are checked first. TST Desk matches one `fnmatch` glob over the whole command line (core/tstd/policy.py:108-139, 210-218). The autonomy classifier already has a shlex lexer with `punctuation_chars=">|&;"` (core/tstd/autonomy/classifier.py:409); reuse it. Directive 6 (every call is classified) is what this protects. Source: https://code.claude.com/docs/en/permissions#tool-specific-permission-rules and https://code.claude.com/docs/en/security#additional-safeguards.

**Update 2026-10-19:** built (backlog TD-5101). A new scanner (core/tstd/policy_shell.py) replaced the shlex reuse, since shlex drops the quoting and positions a rule needs. `env VAR=…` is stripped for `never` and `ask` but not for `auto`; see DECISIONS.md.

### TD-5102 — `fs_grep` content search and path globs
**Size:** 3 · **Depends on:** none
**Acceptance criteria**
- [ ] New built-in `fs_grep` with regex pattern, path, glob filter, case flag, context lines, and modes for files only, matching lines or counts. Results are capped, with a truncation flag. It honors .gitignore.
- [ ] `fs_grep` is Class A inside the workspace wall, so it auto-runs, and it refuses paths outside the wall.
- [ ] `fs_list` accepts path globs like `src/**/*.ts`, can sort by modification time, and reports when it truncates.
- [ ] The steering nudge that points the model at fs_edit/fs_write (TD-5009) also points it at fs_grep instead of shell grep.

**Notes** — Claude Code ships dedicated read-only search tools so searching never needs a shell prompt. Today TST Desk has seven built-ins (core/tstd/tools/registry.py:243-442) and no content search, so every grep is a Class B shell call that asks. This is the most frequent interruption on EZER. Use ripgrep if present, with a Python fallback. Source: https://code.claude.com/docs/en/tools-reference#grep-tool-behavior.

**Update 2026-10-14:** built, with a pure-Python search instead of ripgrep. In-workspace reads were never static Class A, so the second criterion waited on Adam. He pre-approved built-in reads the same day, and TD-5141 adds the rule.

### TD-5103 — Static read-only command list for shell
**Size:** 5 · **Depends on:** TD-5101
**Acceptance criteria**
- [ ] A fixed, parsed list of read-only commands auto-runs without a model verdict. Starting list: `ls`, `pwd`, `cat`, `head`, `tail`, `wc`, `file`, `stat`, `git status|log|diff|show|branch`, `rg`, `grep`, and `find` without `-exec`/`-delete`.
- [ ] Any redirect, chain segment that isn't on the list, write flag, or path outside the wall drops the call back to the normal gate.
- [ ] The list lives in config with a packaged default. Users can shrink it, or turn it off with one key.
- [ ] The audit DB records which list entry allowed each call.

**Notes** — Claude Code documents a built-in set of read-only commands that run without prompting. TD-4805 decided shell is never Class A. This story reverses that only for a static parsed list, so model judgment still never auto-approves shell (approved by Adam 2026-10-14). Evidence: core/tstd/autonomy/classifier.py:460-468. Source: https://code.claude.com/docs/en/permissions#read-only-commands.

**Update 2026-10-20:** built (backlog TD-5103). A listed git command also runs with git's command hooks and in-tree attributes switched off, and git entries need git 2.40+; see DECISIONS.md.

### TD-5104 — Sanitize MCP tool schemas for strict endpoints
**Size:** 2 · **Depends on:** none
**Acceptance criteria**
- [ ] At load, each MCP tool's input schema is checked. Root `anyOf`/`oneOf`/`allOf` are flattened where possible. A schema that still fails validation, or a name longer than 64 characters or containing characters outside `[A-Za-z0-9_-]`, is excluded with a visible warning in Settings and the doctor.
- [ ] One bad tool never fails a whole request. A test registers a bad tool next to a good one and runs a turn against a strict mock endpoint.
- [ ] Excluded tools are listed with the reason.

**Notes** — Claude Code's MCP docs describe skipping tools whose schemas the API would reject. TST Desk only forces `type: object` (core/tstd/mcp/jsonrpc.py:52-62). Strict OpenAI-compatible endpoints and llama.cpp grammar generation both reject odd schemas. Source: https://code.claude.com/docs/en/mcp#tools-with-invalid-input-schemas.

## Decisions (Adam, 2026-10-14)

1. **Chained shell commands (TD-5101):** split the command; an `auto` rule applies only when every segment matches.
2. **Read-only list (TD-5103):** approved. TD-4805 is reversed only for the static parsed list; model judgment still never auto-approves shell.
3. **Hooks (TD-5134):** hooks may come from a trusted workspace config as well as user config.
4. **Steering edits (TD-5140):** agents may propose edits to steering files; only the user's approval writes them. Directive 4 becomes "the agent never writes steering files directly". Built after the safety batch.
5. **Interactive sandbox (TD-5138):** bubblewrap on Linux. Podman stays for autonomy runs.
6. **Remote MCP servers (TD-5136):** an explicit opt-in per server satisfies directive 1.
7. **Worktree per session (TD-5126):** on by default in git repos, with the safeguards in the story.
8. **Order:** local-model wins first (TD-5102, 5104, 5105, 5106, 5109), then the safety fixes (TD-5101, 5108, 5113).
9. **Built-in reads (TD-5141):** pre-approved. `fs_read`, `fs_list` and `fs_grep` inside the workspace auto-run as static Class A, `.env` included; a policy rule can still make a file ask.
